# TradeHQ Newsletter — live AI preview + isolated test email

## Production status and guarantees

- Weekly draft generation remains on the existing Supabase Monday 09:00 Asia/Colombo schedule, using the already configured free Gemini model (subject to actual quota).
- In the private admin desk the owner can press **Preview next week's AI issue**. This uses Gemini to generate a real new sample but does not insert, edit or approve any newsletter edition. The owner can inspect the text before the scheduled edition is generated.
- An approved issue is eligible for exactly one owner-only test delivery **per revision**. The selected edition is fetched from the private database; the browser cannot supply arbitrary HTML, recipient or other email payload.
- **Sending is not enabled by default**. It requires the owner to configure a verified Resend sender. Subscriber publishing is completely disabled and old `public.subscribers` records are NEVER imported or mailed. All requests are independent of the weekly cron.

## Free-tier sending prerequisites (owner action)

1. Create/use a Resend account. Check the current free quota on the account and verify a sending domain using Resend's DNS/SPF/DKIM steps. Do not use an onboarding-only sender as the production identity. Do not upgrade or enable paid overages without authorization.
2. On the connected Supabase project, open **Edge Functions → Secrets**: https://supabase.com/dashboard/project/cbdktpjgczhthflspqjb/settings/functions and set:
   - `RESEND_API_KEY` — your secret Resend API key (never expose it to GitHub, the browser or a chat).
   - `NEWSLETTER_FROM_EMAIL` — a mailbox on the domain Resend has verified, e.g. `newsletter@thetradehq.com` **only if that address/domain has been verified**.
   - `NEWSLETTER_TEST_TO_EMAIL` — the owner's own consented inbox. The server will ONLY send to this exact address. Do not put unconfirmed subscriber emails here.
3. The existing protected Supabase `ADMIN_MASTER_KEY` also needs to remain installed in the Edge runtime. The new sender uses the same constant-time credential check plus request rate limits. Do not share this key.
4. Unlock https://www.thetradehq.com/admin/newsletter with the existing owner key. Check the sender status. Select the already approved edition and press **Send test to my inbox**.
5. Read the receipt. `accepted` means Resend received the API request, **not** confirmed inbox delivery. Check inbox/spam and Resend logs. `rejected` means the provider declined the request; `unknown` may mean the message was accepted despite a network error. The same revision will not send twice automatically.
6. To test a changed edition, reopen, edit and explicitly approve a new revision. Do not bypass duplicate safeguards or try to send to legacy contacts.

## Content view

- The unsaved next-week preview appears in the private newsletter desk as subject, preheader and full Markdown. It is generated by the active free Gemini key on demand; therefore actual preview quality and availability depend on the model/quota.
- The email test sends a clean dark-mode HTML plus plain-text version of **the approved, database-stored issue** (not the unsaved preview). The body is HTML-escaped before adding supported headings/emphasis/HTTPS links to prevent stored HTML injection.
- There is no AI generation or email-send cron in the new test sender.

## Not yet implemented: real subscriber delivery

Before sending even a single marketing newsletter to members, build and verify explicit opt-in (ideally double opt-in), unsubscribe and one-click unsubscribe, bounce/complaint suppression, recipient-specific delivery tracking, provider webhooks, quota throttling, and owner-approved dispatch. Legacy rows have no consent proof and must not be treated as confirmed newsletter recipients.

This isolated test flow intentionally stops short of mass delivery so that a mistaken click or unverified consent cannot contact readers.
