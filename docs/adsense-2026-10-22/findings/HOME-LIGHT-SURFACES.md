# THQ-060 — homepage text on fixed dark surfaces

Full light-scroll homepage captures at all five widths were personally viewed, including all thirteen contact sheets. Four independent actual 390/1280 light/dark hero screenshots after 2.5s settling reproduce the problem: heading, emphasized $100,000, Learn Trading CTA and statistic values inherit rgb(15,15,15) in light mode against positioned black surfaces. Multiple marketing headings and FAQ questions below show the same mismatch. Dark mode is readable. A local solid-background contrast calculation would be misleading because of positioned gradient overlays, so no exact pixel contrast is claimed.

Source components explicitly use fixed dark backgrounds while text consumes global --foreground and --muted-foreground. The prior MegaFooter repair already demonstrates the local dark-palette pattern. Proposed Index wrappers scope that palette only to the hero, MarketPulse and the six consecutive fixed-dark marketing sections; light daily card, answer block, link hub, roadmap and publisher notes retain their existing palette. A light-theme shared navigation background keeps icons visible over the hero without changing menu/auth handlers.

Reviewable proposal only; not implemented or deployed. It changes Index presentation and two light-theme shared navigation classes. Data feeds, prices, order processing, calculations, records, analytics/ad consent, authentication, theme-selection behavior and all wording remain unchanged. Before release: full five-width/two-theme affected surfaces, unaffected light blocks, keyboard FAQs/menu/link navigation, measured solid-background text where applicable, build/CI/native actual preview, protected merge, exact native production and guest smoke. Rollback is an ordinary reviewed revert. PR259's failed native Cloudflare preview is an operational hold, not a reason to bypass release gates.

About and Contact full-light scroll also personally reviewed at all five widths: their foreground content is readable, but the same transparent/light-text navigation mismatch occurs while over the fixed-dark footer. The proposal therefore uses two explicit .light utility variants on Navigation instead of a homepage-only rule. Dark styling and all navigation/auth/menu handlers remain unchanged. This scope refinement requires shared-navigation regression checks on representative other pages.
